# Independent fixed-instance audit: A/S0/j6 partial

Scope: one frozen rational family and its actual tie order, not the registered batch. Input geometry is the 48 center/radius pairs saved in `r037_failure_geometry.json`; its hash and all other source hashes are in `audit.json`. It is treated as the instance to be checked, rather than assuming the original random generation or registered tie-selection protocol was followed. The Python checker imports no producer code.

Each coordinate, radius and active endpoint is scaled by 32768 to an integer. The checker partitions the first two coordinates into exact open cells, and the remaining six by their maximum absolute coordinate; each cell contributes its integer area times `(2 hi)^6−(2 lo)^6`, divided by 32768^8. This reconstructs the union of all original Q, then repeats with all original Q and the selected E=(a+4)Q. Points on boundaries have zero volume. It separately recomputes the largest-radius eligible history using the frozen order and all center tests; no test lands exactly on a bQ boundary for any selected center.

The reconstructed history is [0,2,3], n=8, a=4, τ=3/131072, with increments 256 each and p=1/65536 each. The two rejected E-incidence classes are {2,3} of volume 128 and {0,2,3} of volume 664695128772458341867117494959079427/5192296858534827628530496329220096. Their total p values are strictly above τ; proportional flows are explicitly in `audit.json`, match the frozen q and preserve sum_i h_i q_i=|U| exactly. The common witness input f=(11/10) 1_{union V_i} makes every original V_i admissible at λ=1.

All 48 witness boxes are independently intersected using exact strict interval inequalities. A fresh Bron–Kerbosch enumeration without a node cap returns exactly the 40 frozen maximal cliques, and therefore every positive-volume witness load is accounted for by a listed clique. Vertices 2 and 3 are nonadjacent and h_2=h_3=16777216. Consequently the vector z_2=z_3=1 and all other z_i=0 is feasible for the dual packing problem: M(V)≥33554432, giving Lopt≤|U|/33554432. The explicit payment vector q'_2=q'_3=|U|/33554432 with all other entries zero conserves total payment and has load exactly that upper bound, since no clique contains both 2 and 3. This supplies an actual improved feasible payment, not merely an LP direction. It does not establish that the global optimum equals this upper bound.

Every positive initial q is supported on a vertex with globally maximal h. For any clique C, if it carries payment then max_{i∈C} h_i is that global maximum, so its compression savings s_C=sum_C q_i−sum_C h_i q_i/max_C h_i=0; if it carries no payment, s_C=0 as well. Thus no positive-s move exists for **any** clique, including every candidate pool and every subclique. L0−|U|/33554432 is strictly positive and equals approximately 8.9011155093e−6, or 22.58068% of L0. The exact fractions, independent proof checks and measured CPU, wall, peak RSS, PID and file hashes are recorded in `audit.json`.

This is a concrete finite payment-history counterexample to this compression mechanism, with a fixed legal order. It is not a registered H batch frequency, a claim about every compression algorithm, or a new bound on C_n. Source files reflect known departures from the registered batch generation and tie protocols.
