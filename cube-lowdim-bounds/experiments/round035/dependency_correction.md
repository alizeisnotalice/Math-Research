# 公共 first 核验器的积分回调依赖更正

本次仅静态追踪源码和读取既存简短日志/运行meta，没有积分、核点、全域核验或模型重跑。该问题影响旧 first 路线的严格性说明，不能只当作第35轮新适配器的局部事项。

## 已定位的两处契约缺口

锁定公开 `hlcert.py` 的 SHA256 为 `4bd7e823bdcb336f8e20c188d68d6d8c1e4aa22ec52353885059c24445317db5`。

1. `Apsi_outside_point`（约473—489行）：`acb.integral(f,...)` 的回调接收 `analytic`，但三个复对数均使用不带该标志的 `.log()`。
2. `_Hint`（约361—384行）：公共 `pw=lambda z,e:exp(e*z.log())` 不接收回调的 `an`。H、Ha、Hb、Haa、Hab、Hbb_int六种回调均经过它，因此全部有同一契约缺口；只修H不足以修复外区Taylor模型。

[python-flint 的官方 `acb.integral` 文档](https://python-flint.readthedocs.io/en/latest/acb.html#flint.acb.integral) 要求：当回调的解析性参数为真时，需要在整个输入复杂球上验证解析性，否则返回非finite；含log等分支函数时必须处理这一标志，即使实路径避开分支。应使每个幂的log使用 `log(analytic=an)`（或等价的正确带标志幂运算）。`.exp()`是整函数，不需额外分支处理。实路径各对数参数正，只证明原积分存在，不能替代复杂球上的契约。

尚未运行修正程序，也没有发现一个已保存积分数值实际错误的证据。结论是这条API用法不能作为已建立的严格积分包围依据，而非已证其每次结果均错误。

## 实际依赖路径

`cert_run.py:A_cell -> Kern.A_lower -> Kern.sing_parts`。

`sing_parts`首先调用`sing_mono`；若盒的`rmax>R`，后者把`Apsi_outside_point(u1,v1)`纳入候选下界。因此外区常数路线不能绕开第一处问题。严格外盒满足`rmin>R`且`rmin-R<1/2`时，还调用`_outside_taylor`；其中心值、梯度和Hessian余项通过`_Hint`的上述六种积分构造，继而影响Bernstein多项式与余项。

内区`I0/I1/I2`本身调用`J`的2F1闭式，不是另一处`acb.integral`。它们不能用于替旧外区结果辩护，也没有被本次问题直接波及。K的有限样条/实幂检查和准确成本运算不调用这两个积分口。

第1轮旧缩放first运行确实正常exit0、日志记K失败0、A评价219732盒且失败0；这些是历史执行事实，保持不变。但其C4有效性依赖上述有缺口的外区路径，不能再把它称为已经具备完整严格性保证的第二份全域证明。更正不改写旧源码hash、旧run/log/report，也不能给旧报告换上修正源码hash。
