## 1. 理论递推及通用整数分母

固定 \(\beta=3/4\)、\(r_{ij}=M_{ij}\)，十条边顺序为
`01,02,03,04,12,13,14,23,24,34`。对多重指标 \(k\)，记 \(|k|=n\)。沿用已证形状变换
\[
 F(t)=\mathbb E_R(1-\sum_e t_er_e)^{-\beta}
 =\left[\frac1{16}\sum_{v\in V}(1-\sum_{i<j}t_{ij}v_iv_j)^\beta\right]^{-1}. \tag{1}
\]
在 \(t=0\) 邻域所有 \(|r_e|\le1\)，故可以作解析幂级数系数比较。
字符乘积的平均为一当且仅当多重图每个顶点的度数为偶数，否则为零。
分母的每个非恒定 Euler 图系数恰为
\[
 -\frac{C_m}{4^m\prod_e j_e!},\qquad
 C_m=3\prod_{s=1}^{m-1}(4s-3),\quad m=|j|\ge1.
\]
同时定义
\[
 D_n=\prod_{s=0}^{n-1}(4s+3)=4^n(\beta)_n,\qquad
 B_k=D_n\mathbb E_Rr^k,\qquad B_0=1.
\]
因为 \([t^k]F=B_k/(4^n\prod k_e!)\)，从分母乘 \(F=1\) 比较系数得到
\[
 \boxed{B_k=\sum_{0<j\le k,\ j\text{ Eulerian}}
 C_{|j|}\prod_e\binom{k_e}{j_e}\,B_{k-j}.} \tag{2}
\]
奇度图矩为零。式 (2) 的每个依赖严格降阶，所有项均为非负整数，因而可用 DAG
缓存；并有 \(0\le B_k\le D_n\)，上界来自 \(|r^k|\le1\)。实现逐次核验该范围。
这里 \(C_m\) 是生成函数系数序列，无需将它解释为经典概率 cumulant。

坐标置换保持 \(R\) 分布，故 \(B_k\) 在 \(S_5\) 的 120 个顶点置换下不变。
实现以 120 个变换中的最小打包键作为规范图，缓存 **规范图→完整整数 \(B_k\)**。
分母 \(D_n\) 不必约分；`expectation` 接口会用 GMP 有理数输出约分结果。

## 2. 编码、接口与 overflow 消除

源文件是 `round012_graph_moments_gmp.hpp`；基本用法：

```cpp
#include "round012_graph_moments_gmp.hpp"
round012::Engine engine(cache_path, header_sha256, 120.0);
round012::Counts k{26,0,0,0,0,0,0,0,0,0};
mpz_class B = engine.B(k);
mpz_class D = engine.denominator(26);
mpq_class moment = engine.expectation(k);
engine.sync();
```

`engine.B(uint64_t code)` 兼容 Astra005 的 **五位**边重数编码，`canonical(code)`
使用同一最小编码约定。安全的数组入口 `encode/ B(Counts)` 会显式拒绝边重数或总次数超界。
十个五位字段占 50 bits；当前接口明确支持 **总次数≤31**，覆盖所需的 26。
这不是“任意次数图编码”；未来超过 31 次应改数组键/协议，而不是让字段进位。
原四位字段无法表示单边重数 26，这一问题与整数分子溢出是两项独立缺陷。
使用原始键相加的消费者须保证每个边重数之和≤31；当前全图最高次数 26 自动保证这一点。

`mpz_class` 用于 \(D_n,C_n,B_k\)、递推二项式与其乘积；不会发生固定整数宽度的
回绕。固定宽度类型仅用于已检查的图键、顶点 parity、资源计数及校验和。
FNV 校验和的模 \(2^{64}\) 运算是明确的文件校验操作，不参与数学整数值。
完整空间消费者的 factorial、多项式累加与 multinomial 也须使用 `mpz_class`；
仅升级图矩返回值不能修复消费者的 64 位阶乘。GMP 对象的零测试应写 `q != 0`。

编译采用 Apple clang 21.0.0、C++17，`-Wall -Wextra -Werror` 已通过。
GMP 头文件用 `-isystem`，避免将其已有的旧式 literal operator 声明警告提升为项目错误。
没有修改 GMP，也没有修改 astra004/005 冻结或工作源码。

## 3. 持久缓存和 120 秒停止点

非空 cache 路径要求传入 64 位十六进制的 **header SHA-256**。journal 首行锁定
协议、\(\beta\)、边顺序/五位编码以及该源码指纹。不同指纹被拒绝，不静默复用。
每个完整记录为规范键、十进制 \(B_k\) 和逐行 FNV 校验和；载入时检查校验和、
规范性、Euler parity、次数及 \([0,D_n]\) 范围，冲突重复记录会报错。
这些完整性检查不能把外部不可信的伪造矩表变成数学证明；缓存应来自锁定源码的可信生产。
本轮还在最终结果中记录了整份外置 journal 的 SHA-256。

实现用独占 `flock` 防止两个写进程交错，同步写入完整行；每 64 个完成子矩、
显式 `sync()` 和正常析构时 `fsync`。突然停止后，已有完整子矩仍可复用；仅删除
最后一个不完整行，完整但校验失败的行会报错。初始协议头损坏不会被冒然解释成有效缓存。
规范化原始键缓存默认上限 500000 项，达上限时清空后重建；完整矩缓存不会据此删除。
完整矩缓存及 journal 载入仍占内存；本轮没有实现磁盘分页或给未来全空间规模保证 RSS。

每个 Engine 默认每约 256 个递归检查点检查 120 秒软截止。到时抛
`round012::CheckpointStop`，未完成的当前 \(B_k\) 不进入缓存，已完成子矩保留；
重建相同 Engine 即续算。另有 `max_new_moments` 用于确定性的恢复测试。
120 秒是单次可恢复检查点，**不是总算力预算或永久放弃条件**。

图缓存不自动保存空间多项式累加。完整空间消费者应在完成一个 \(W^n\) 后保存
空间 family 与 `last_completed_n`；若中途停止，只重放该未完成块，不能把半完成累加再加一遍。
也可明确以 `Engine(...,0.0)` 关闭内置时间点，自己控制分块和日志。
Astra005 已明确采用后者并逐完整 \(n\) 同步图 journal；其空间恢复策略由该任务负责。

## 4. 实际高阶试点和独立准确交叉

本轮按 `round012_registration.json` 唯一预登记的三个目标执行。先在第 10 个完成子矩后
主动暂停，journal 中写入 7-byte 残片 `partial`，随后重开同一缓存并继续原三个目标。
恢复程序准确加载 10 个子矩并截去 7 个尾字节，最后三个目标全部完成。

| 目标 | 边重数向量（上述顺序） | 准确期望 |
|---|---|---|
| 单边26 | \((26,0,0,0,0,0,0,0,0,0)\) | \(43119702416260199/14675129178108858921\) |
| 三角18 | \((6,6,0,0,6,0,0,0,0,0)\) | \(287475548519528113/70480077251904923603\) |
| 四环22 | \((6,0,4,0,6,0,0,6,0,0)\) | \(11879768794484875848037/4277233445643024554642955\) |

单边的独立算法用有理普通 Taylor 系数求逆
\[
 \mathbb E_R(1-zr)^{-3/4}=\frac2{(1-z)^{3/4}+(1+z)^{3/4}},
\]
再乘 \(26!/(\beta)_{26}\)。三角的独立算法取四种符号组 \((A,B,AB)\)，直接对
\[
 \left[\frac14\sum_{A,B=\pm1}(1-Ax-By-ABz)^{3/4}\right]^{-1}
\]
作三变量 `Fraction` 系数反演，提取 \((6,6,6)\) 并乘 \((6!)^3/(\beta)_{18}\)。
两者都没有调用图 canonicalization、\(C_m\) 或整数 \(B_k\) 递推，均与 GMP 输出准确相等。
四环本轮由新后端计算，未另宣称独立交叉。

单边的完整整数为
\[
 B=1921695688017576803223777768906945796875\quad(131\text{ bits}),
\]
\[
 D_{26}=654019644904558303836431802744185605453125\quad(139\text{ bits}).
\]
这不是根据位数估计猜测旧后端会失败，而是实际运行得到的超界整数。

实际资源：暂停运行的 Engine 计时约 0.00261 秒、子进程墙钟约 0.649 秒；
恢复 Engine 约 0.00652 秒、子进程墙钟约 0.01235 秒。独立 Python 交叉约 0.01672 秒。
冷启动开销与内核计时不同，均只作实际记录。恢复后新算 93 个规范子矩，合计缓存含零图
104 项、原始规范化缓存峰值 366 项；恢复段访问 21599 个 subset 叶；journal 为 4235 bytes。
未采集峰值 RSS，不用缓存项数伪装 RSS。二进制和缓存全部留在仓库外。
这些小图只有少量非零边，**不能用其速度预测完整高阶空间证书**。

## 5. 二次 Z 的空间规模检查点

对 Astra005 的二次 \(Z\)，所需 \(d,d^2\) family 到 \(W^{14}\)、\(b\) family 到
\(W^{22}\)，最高图矩次数 26。固定的准确组合计数为：

| 容器/展开规模 | 数量与含义 |
|---|---:|
| \(W^{22}\) 的十边重数分配 | \(\binom{31}9=20160075\) |
| \(W^0,\ldots,W^{22}\) 全部原始分配 | \(\binom{32}{10}=64512240\) |
| 全部 degree26 原始十边图 | \(\binom{35}9=70607460\)，并非所需规范 Euler 图数 |
| \(X_i=x_i^2\)，总次数≤23、每坐标≤12 的五变量 partition 容器 | 1565 |
| 四维面上每坐标 degree12 的 Bernstein 张量系数 | \(13^4=28561\)/候选 |

最后两项来自 \(bW^{22}\) 的 \(x\) 总次数 46、单坐标最高 24；符号平均后换成 \(X\)
即总次数≤23、单坐标≤12。1565 是统一容器的准确 partition 数，不表示所有系数都非零，
也不是每个 family 块都需要 1565 项。结果 JSON 保存逐总次数的完整计数。
没有从这些计数推出完成时间、内存上界或 positivity；完整空间展开和连续域证书仍须实际执行。
