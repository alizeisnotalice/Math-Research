# Required pre-proposal lookup fields

For every proposed upper-bound mechanism, fill these fields and cite source path plus SHA-256 (or mark not supplied):

1. **Object/target:** centered or uncentered; axis-parallel or other; common radius or independent side lengths; measure; (L^p) input; dimension; all radii or restricted radii.
2. **Normalized model:** exact frame/direction set and ordering; scalar weights on every column; exponent α; symbol (\psi(\xi)\); common-time convention; Fourier normalization; probability/Lebesgue normalization; any dilation convention.
3. **Parameters:** every frame parameter (e.g. β), cutoff (T), threshold (m), spatial partition, and which values were actually tested versus only defined.
4. **Proof scope:** fixed point, fixed time/cutoff, all positive times, all spatial points, all cube, positive face, or actual operator constant. State which quantifiers are paid.
5. **Proven interface:** exact implication/formula and hypotheses; distinguish kernel/model-cost proxy from actual (C_6).
6. **Paid objects:** exact global/pointwise/interval certificates and their domain.
7. **Unpaid object:** exact remaining infimum, integral, coverage, tail, singular-stratum or parameter claim required to reach the proposed bound.
8. **Prior match:** candidate registry ID; if matching, explain whether only the identical mechanism, a new parameter value, or a genuinely different normalized model is proposed. Link all directly relevant source reports and hashes.
9. **Execution status:** distinguish historically reported executed runs from this lookup; no inherited status by title alone. Any new run needs primary-owner authorization and a bounded registration.
10. **Novelty status:** one of `same full mechanism`, `parameter variant of registered mechanism`, `different full normalized model`, or `not found in bounded registry; novelty undetermined`. Never infer novelty from missing registry text.

This checklist routes work only; it is not a mathematical certificate or execution authorization.
